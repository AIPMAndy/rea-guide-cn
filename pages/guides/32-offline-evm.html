32｜EVM 字节码只读结构调查

目标：明确静态推断和实际链上行为的界线。
适用对象：Offline EVM｜审核日期：2026-10-21｜证据状态：O 上游描述，E 操作方案，未获得 T-REA 实测结果。

返回首页 · 官方功能表 · 证据等级 · 安全许可

你要解决的具体问题

明确静态推断和实际链上行为的界线。建议先做一个自己编译、能够公开完整输入输出的样例。REA 上游列出的能力可能尚未进入正在使用的 npm 版本，必须检查本机的 rea --help、rea capabilities 或所安装包实际清单。

环境与授权检查

  • 文件来源、授权范围、版本、SHA256 和可公开的输出边界已记录。
  • 已确认此类型在 当前已安装发行版 可用，而非仅在 GitHub 主分支存在。
  • 若需要外部工具，单独核对系统支持、许可证、版本和工具链安装方式。
  • 只读为默认模式；运行、提取、文件改动、捕获流量前单独审批。

六步完整流程

步骤 1｜仅选择你自己编译的简易 Solidity 教学合约，记录源码版本及编译配置。

步骤 2｜保存 EVM 字节码和编译器信息，严格使用本地测试样本，不使用真实钱包密钥。

步骤 3｜在官方文档中确认离线 EVM 分析的操作系统约束与 CLI 入口，避免将非发行版功能写成可用。

步骤 4｜只读提取函数选择器、字节偏移、控制流特征与可能的参数信息。

步骤 5｜用公开 ABI 或自有源码验证可核实的选择器映射；不推断合约没有安全漏洞。

步骤 6｜结果记录静态结构，明确没有连接链、没有发交易、没有触发资金行为。

可复制任务指令

目标：分析本地教学合约字节码，输出选择器和可验证字节偏移，拒绝资金或真实账户操作，不对安全性做保证。
分析目标：【自己编译或具有明确授权的样例绝对路径】
授权范围：【所有权/许可与禁止事项】
环境：【系统/REA版本/Node版本/可用provider/辅助工具】
安全约束：先仅做只读分析。未被明确批准前不运行不可信程序，不自动联网、不解密、不绕过许可、不读取或外传任何私人账号、密钥、证件与客户数据。
交付：操作与证据对应表、实际命令、原始文件与哈希、直接观察、推断、反证、失败信息及下一次最小测试。
失败策略：若能力不存在或命令返回不支持，记录事实并停止，不构造不存在的参数或假装已完成。

证据与推断对照表

支持该类型的检查 当前版本的 --help / 实际返回 本机查看、保留退出码 本机版本已证实 / 未验证

推断程序行为 静态关系或元数据 独立运行样例与边界测试 假设，需进一步证实

失败场景与红队审核

主要风险：仅有函数选择器无法证明权限控制或资金行为安全。

  • 若无法找到真实来源/数据，应标明“未验证”，不得由 AI 补造文件位置或函数地址。
  • 不能依赖某个工具的“成功”字符串证明真实业务结果；重要结论需以自有样例复验。
  • 避免在 GitHub Issue 分享未脱敏的原始程序、截图、网络载荷、密钥与合同资料。

验收清单

  • 能提供自己有权使用的目标文件与复现环境。
  • 至少三项结论明确区分直接观察 / 推断 / 待验证。
  • 至少一个可推翻主结论的测试与预期结果已经列出。
  • 记录工具版本、辅助依赖、完整命令、退出状态与人工复核情况。
  • 如果未执行 REA，明确标记“未运行 REA”，不使用想象中的工具输出。
