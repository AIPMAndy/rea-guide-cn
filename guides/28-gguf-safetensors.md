## 你要解决的具体问题

不加载未知模型也能盘点模型文件元数据。建议先做一个自己编译、能够公开完整输入输出的样例。REA 上游列出的能力可能尚未进入正在使用的 npm 版本，必须检查本机的 `rea --help`、`rea capabilities` 或所安装包实际清单。

## 环境与授权检查

- [ ] 文件来源、授权范围、版本、SHA256 和可公开的输出边界已记录。
- [ ] 已确认此类型在 **当前已安装发行版** 可用，而非仅在 GitHub 主分支存在。
- [ ] 若需要外部工具，单独核对系统支持、许可证、版本和工具链安装方式。
- [ ] 只读为默认模式；运行、提取、文件改动、捕获流量前单独审批。

## 六步完整流程

### 步骤 1｜使用自己生成的极小 GGUF 或 safetensors 测试文件，或公开授权模型文件。

### 步骤 2｜记录模型文件实际路径、总大小、SHA256 与许可来源，确认允许存储和分享哪些字段。

### 步骤 3｜检查当前 REA 是否提供只读模型头检查，区分支持的文件格式与安装版本。

### 步骤 4｜提取头信息、tensor 声明、维度、数据类型及统计总量；不要求系统加载权重或运行推理。

### 步骤 5｜人工验证文件大小、声明数量与结构一致性，检测截断、冲突或不合理元数据。

### 步骤 6｜报告“模型元数据”，绝不从文件头推断模型训练来源、真实性能或安全性。

## 失败场景与红队审核

**主要风险：**模型头可伪造、损坏；tensor 名称不证明训练来源与模型效果。

- 若无法找到真实来源/数据，应标明“未验证”，不得由 AI 补造文件位置或函数地址。
- 不能依赖某个工具的“成功”字符串证明真实业务结果；重要结论需以自有样例复验。
- 避免在 GitHub Issue 分享未脱敏的原始程序、截图、网络载荷、密钥与合同资料。
